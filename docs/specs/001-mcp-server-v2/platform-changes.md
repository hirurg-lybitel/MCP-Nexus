# Изменения в платформе Гедымин

**Правило проекта (D18):** разработка MCP-сервера не вносит изменений в исходники и сборку платформы. Всё, что можно, решается на стороне MCP-сервера и штатными средствами Гедымина (скрипт-функции, пространства имён, `gedemin.ini`, `firebird.conf`). Сюда записывается то, что без правки платформы сделать нельзя или можно только с заметными ограничениями: что изменить, где и зачем. Файл передаётся автору платформы; решение о внесении принимает он.

Ссылки на код — `D:\Git\gedemin-private`, ветка `delphi7` (сборка 2.9.7.13137).

## Обязательные изменения

Нет. Для всех найденных проблем есть обходной путь на стороне MCP-сервера.

## Желательные изменения

Каждое снимает ограничение обходного пути. Без них сервер работает.

| № | Что изменить | Где | Зачем | Обходной путь в MCP-сервере и его ограничение |
|---|---|---|---|---|
| П1 | В тихом режиме (`/Q`) не показывать `MessageBox` при слишком длинном SQL отчёта, а поднимать исключение, которое видит вызывающий скрипт | `Gedemin/Transaction/gdvAcctBase.pas:479–486` (`BuildReport`, обработка `EgsLargeSQLStatement`) | Сейчас воркер блокируется модальным окном, а после его закрытия возвращает **пустой отчёт**, который выглядит как нули | Супервизор воркера находит модальное окно процесса воркера, закрывает его и возвращает ошибку «отчёт слишком большой»; сервер заранее ограничивает число счетов и аналитик в одном запросе. Ограничение: запрос ждёт срабатывания супервизора (секунды), часть больших отчётов приходится делить |
| П2 | То же для ошибки загрузки сохранённой конфигурации отчёта | `gdvAcctBase.pas:693–698` (`LoadConfig`) | Модальное окно при битой конфигурации | Супервизор закрывает окно и возвращает ошибку; конфигурации проверяются пробным запуском при построении каталога |
| П3 | Не показывать `MessageBox` при ошибке привязки порта веб-сервера в тихом режиме, а писать в журнал и завершаться с кодом ошибки | `Gedemin/Component/gd_WebServerControl_unit.pas:823–832` | Воркер зависает на старте, если порт занят | Супервизор проверяет, что порт свободен, до запуска воркера |
| П4 | Параметр `gedemin.ini` для кодировки ответов веб-сервера (UTF-8) | `gd_WebServerControl_unit.pas:683–704`, `1504–1520` | Все ответы сейчас в Windows-1251 | Обработчики воркера отдают JSON только из ASCII-символов: всё остальное экранируется `\uXXXX`. Кодировка ответа тогда не важна |
| П5 | Параметр `gedemin.ini`, отключающий служебные адреса (`/OData`, `/get_blob`, `/get_file`, `/get_files_list`, `/query`, `/test`, `/relay/*`); экранирование имён таблицы и поля в `/get_blob` | `gd_WebServerControl_unit.pas:599–765`, `1136–1167` | Служебные адреса работают без авторизации; `/get_blob` подставляет параметры в SQL конкатенацией | Веб-сервер воркера слушает только `127.0.0.1`; обработчики воркера проверяют общий секрет в параметре `token`. Ограничение: любой процесс на той же машине может читать данные через `/OData` |
| П6 | `GD_P_SEC_LOGINUSER` возвращает `IBNAME`/`IBPASSWORD` только при `RESULT = 1` | `Gedemin/SQL/gd_security.sql` (процедура `GD_P_SEC_LOGINUSER`) | Сейчас учётные данные Firebird выдаются и при неверном пароле | Владелец сообщил автору платформы (Q14). Сервер исходит из того, что порт Firebird закрыт за пределами доверенной сети |
| П7 | `Dataset2JSON` для любого набора данных, а не только `IgsIBSQL` | `Gedemin/Report/obj_Gedemin.pas:574–640` | Наборы данных бухгалтерских отчётов (`TgdvAcct*`) нельзя сериализовать штатной функцией | Обработчик воркера на VBScript обходит набор данных и сам формирует JSON (вместе с П4) |
| П8 | Ключ командной строки для скрытого интерфейса (`HideUI`) вне режима `/AUTOTASK` | `Gedemin/Security/gd_CmdLineParams_unit.pas:224–498` | Окна воркера появляются на рабочем столе | Запуск свёрнутым окном от отдельного пользователя Windows или в отдельном сеансе |
