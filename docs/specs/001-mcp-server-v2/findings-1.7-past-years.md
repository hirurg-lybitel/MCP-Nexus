# 1.7 Черновик: проводки за прошлые года / закрытие периода

Дата: 2026-11-03. База: `CRM_WORKER.FDB`.

## Что искали

Операции и функции, связанные с переносом/закрытием прошлых периодов.

## Наблюдения

- В `AC_TRANSACTION` 231 типовая операция. Поиск по ASCII-шаблонам `PRIOR`/`CLOSE`/`YEAR` в имени не дал однозначных совпадений (имена в Windows-1251; нужен запрос с правильной кодировкой клиента или через MCP `run_sql` после починки schema output).
- Среди топ операций Амперсант 2022 (inventory-snapshot) доминируют обычные складские/кассовые/банковские операции, не «закрытие года».
- Правило D9 уже покрывает `AC_TRANSACTION.ISINTERNAL = 1` (5 таких типов, тысячи сторон исторически).

## Решение (пока)

1. Не блокировать этап 1: закрытие периода оформить отдельным контрольным вопросом C15/C16 (`needs-accountant` + авто-поиск по имени после UTF-подключения).
2. При реализации тула `get_posting_stats` включить группировку с флагом `isinternal`.
3. Повторить поиск через `run_sql` с `CAST(... AS VARCHAR(...))` / соединение WIN1251, когда удобно.

Статус: **отложено**, не блокер критерия перехода этапа 1 (ОСВ + схема уже закрывают ядро).
